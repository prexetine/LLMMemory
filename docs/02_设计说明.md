# 02 设计说明 —— ToyMemory 记忆提取 Agent

> 面向技术评审与后续规划。回答三个问题：**关键设计是什么**、**数据怎么流**、**已知问题在哪**。
> 运行与排障见 `01_操作手册.md`。

---

## 1. 一句话定位

从已筛选的儿童对话与照片日志中，用 LLM 提取候选记忆事实，经**证据核验 → 来源审核 → 修订 → 关系裁决 → 分类 → 历史维护**后，以**单 Session 原子事务**写入 SQLite，并导出双 HTML 与 106 维记忆书页。

核心工程主张：**模型只负责语义理解，所有结构、门禁、时间、证据定位由程序决定。**

---

## 2. 架构总览

```
memory_agent.py            配置、批次锁、用户调度、汇总
   └─ agent_parallel.py    用户级进程并行(≤3)，同用户串行
        └─ GenericPipeline 唯一编排（agent_generic_flow.py）
             ├─ agent_context.py        有界上下文、分窗、分页、容量预检
             ├─ agent_llm.py            单次网络发送 + 调用日志
             ├─ agent_stage_runtime.py  阶段/条目缓存、共享重试预算
             ├─ agent_contracts.py      候选/信号/比对契约、证据核验
             ├─ agent_fact_policy.py    事实粒度、范围、保存去向
             ├─ agent_prompts.py        唯一在用的提示词
             └─ agent_maintenance.py    Session 原子事务
                  └─ memory.sqlite3     唯一权威真源
                       └─ memory_view_data.py → export_memory_html.py  双 HTML
```

**关键设计原则**：生产只有**一个运行入口**和一个编排类。旧的推荐规则核心（`main.py`、`behavior_service.py` 等）与 `tests/legacy_*.py` **不属于本链路**。

## 3. 主流程（`GenericPipeline._run_core`）

| 步 | 阶段 | 做什么 | 失败处理 |
| --- | --- | --- | --- |
| 1 | 结果缓存 | 命中 `session_result` 缓存且回执存在 → 直接返回 | 零模型调用 |
| 2 | 回执恢复 | 有 `v3_receipts` 但报告丢失 → 从 SQLite 重建 | 不重新提交 |
| 3 | 分窗 | 按 `session_chunk_*` 完整二分，保留 `source_spans` | **从不静默截断原文** |
| 4 | 路由 + 提取 | `source_router` 选 Skill → 每 Skill 独立 `source_extractor` | 只拆失败的 Skill |
| 5 | 汇总 + 换人 | 排序 `subject_switch`，回填主体 | 未识别换人 → `unresolved` |
| 6 | 证据核验 + 审核 | `verify_evidence` 逐字核验 → `source_reviewer` 三项 checks | 按来源组批 |
| 7 | 定向修订 | 只修有明确建议的父候选，子候选重新审核 | 逐父项缓存 |
| 8 | 关系裁决 + 分类 | 同源一致性 / BGE 召回关系；分类独立于来源 | 分歧 → `pending` |
| 9 | 维护 + 提交 | 内存预演 → `apply_decision` → 原子事务 | 有重试任务 → **整场不提交** |

## 4. 关键不变量（改动代码前必须理解）

### 4.1 模型职责边界

| 约束 | 实现位置 | 原因 |
| --- | --- | --- |
| 不得输出 `quote`，只能给 `evidence_id/speaker/start/end` | Schema + `verify_evidence` | 防止模型自造引文 |
| `valid_from`/`valid_to` Schema 锁死为 `null` | `agent_flow_schema.py` | 时间只能由程序从 `time_reference` 解析回填 |
| 提取阶段 `operation` 强制 `new`、`target_memory_id` 强制空 | `agent_contracts.py` | 提取阶段不得决定历史更新 |
| `dimension_id` Schema 锁死为 `UNCLASSIFIED` | `agent_flow_schema.py` | 分类由独立模块负责 |
| 助手内容不能成为用户事实证据 | `agent_memory_structure.py` | 助手只能进 `structure.steps` 的 hint/feedback/context |

### 4.2 证据凭证链

- **模型给定位，程序填引文。** `reference_resolver` 把定位解析成实际可见证据。
- **`basis_refs` vs `basis`**：前者是模型定位接口，后者是程序回填后的存储接口。
- **`seal()` / `proof_hash`**：来源凭证绑定内容；`verify_source` 校验 policy、candidate_version、`input_hash`、device、session、`context_hash`、图片 `image_sha256`。
- **分类不修改凭证**：`content_hash` 只绑定事实，所以标签变化**不会**作废来源凭证。

### 4.3 提交原子性

- **粒度是 Session**，不是单条事实。任一 `retry_tasks` 非空 → 整场 `deferred`（"不提交半个 Session"）。
- 事务内**重放验证**：重算 `base_hash` / `history_hash` / `result_hash`，不一致即拒绝。
- `v3_receipts` 提供幂等：已提交 Session 续跑时直接恢复，**不重新调用模型、不重复增加支持次数**。

### 4.4 禁用维度

```
FORBIDDEN = {P01, P05, E02} ∪ {P08 … P16}
```

Schema 允许提交，但契约层拒绝，报「该维度缺少统计/媒体来源」。

## 5. 数据真源与存储

| 表 | 性质 |
| --- | --- |
| `sessions` / `evidence` | 输入与证据 |
| `memories` / `memory_evidence` / `keywords` | **权威记忆投影** |
| `v3_state` / `v3_plans` / `v3_receipts` | 会话状态、维护计划、**原子回执** |
| `reviews` / `memory_reviews` | 审核凭证 |
| `changes` | 候选 → 记忆的映射 |
| `context_work` | **阶段检查点（不是记忆）** |
| `dense_cache` / `dense_index` / `dense_cache_epoch` | **可重建向量缓存（不是真源）** |

**记忆状态**：`reviewed`（当前有效）/ `conflicted`（冲突未决）/ `pending`（待确认）
**维护动作**：`new` / `reinforce` / `coexist` / `supersede` / `conflict` / `pending`

## 7. 实测产出情况（一次 5 用户实跑）

数据来自早前实跑 `memory_agent_core_top5_0907_source_relation_fix`（5 用户，1170 Session，3868 候选）。
> 该次的原始产物（`report.json` 等）**已从交接包中移除**，以下为当时测得并经复核的汇总数字；本节表格即完整数据，无需回查原始 JSON。

### 7.1 全流程漏斗

| 阶段 | 数量 | 占候选 |
| --- | --- | --- |
| 提取候选 | 3868 | 100% |
| 来源审核 `pass` | 3115 | 80.5% |
| 来源审核 `pending` | 145 | 3.7% |
| 来源审核 `reject` | 607 | 15.7% |
| 维护后 `approved` | 2562 | 66.2% |
| ├ `retention=event` | 1613 | 41.7% |
| ├ `retention=session_record` | 633 | 16.4% |
| └ **`retention=memory`（长期层）** | **316** | **8.17%** |

### 7.2 维度使用情况

| 指标 | 数值 |
| --- | --- |
| 维度 `UNCLASSIFIED` 占比 | **65.1%**（8E41 单用户为 84.0%） |
| 实际用到的维度数 | **72 / 106** |

### 7.3 需要注意的分布异常

`retention=memory` 在各用户间**差异极大**：

| 用户 | 候选 | memory | memory 占该用户候选 |
| --- | --- | --- | --- |
| `...92A5` | 862 | **9** | **1.0%** |
| `...9432` | 488 | **130** | **26.6%** |
| `...950A` | 1019 | 47 | 4.6% |
| `...A7F0` | 710 | 52 | 7.3% |
| `...A861` | 789 | 78 | 9.9% |

**同一模型、同一配置，长期层产出率相差 26 倍。** 这不像真实的儿童差异，更像 P0-2（价值判断依赖来源属性）在不同数据上的放大效应 —— `92A5` 的候选大量带会话级 `scope`，于是被整体降级。**排查 P0-2 时应优先看 `92A5`。**

> 对照：更早的 v4 流程（`memory_agent_seed_top5_0907_photos_v4`，703 候选）来源审核 `pass` 125 / `pending` 139 / `reject` 7，`pending` 占比约 20%，远高于本次的 3.7% —— `pending` 比例受流程版本影响很大，跨版本对比需注意。

## 8. 已知问题（重要 —— 交接必读）

以下为代码与实测数据分析的结论，**尚未修复**。按影响面排序。

### P0-1 维度体系与控制逻辑耦合

`dimension_id` 同时承担六个职责：模型分诊、语义分类、Skill 归属、存储分区、入库门禁、下游 API 契约。六个职责的优化目标互相冲突。

**表现**：`agent_flow_schema.py` 强制只填 `UNCLASSIFIED`，`agent_prompts.py` 要求"不按 106 维生成"，而 `agent_contracts.py` 又要求"维度必须属于当前 Skill"。模型**两条路都是错的** —— 老实填 `UNCLASSIFIED` 则 106 维体系在生产链路从未真正生效；尝试分类则被契约层驳回。

**实测**：`UNCLASSIFIED` 占 65~84%，106 维中 72 个从未被使用。

### P0-2 价值判断依赖来源属性（四跳耦合）

```
structure.type → fact.type → scope → retention
```

`agent_fact_policy.py` 的 `retention()` 会因 `scope` 以 `session:` 开头而把 `retention=memory` **强制改判为 `event`**。而 `scope` 是"事实适用范围"，不是"保存期限"——两者被混为一谈。

**后果**：**"在单次会话里说出的喜好"永远拿不到长期记忆身份**，而儿童 90% 的表达是零散短句。

**这是「提取 100 条只写 5 条」的直接根因。**

### P0-3 `pending` 是不可回捞的黑洞

来源审核返回 `pass/pending/reject` 三元制，`pending` 无任何复核或恢复路径。

**实测**：v4 流程中 `pending` 占 24~52%；维护动作中 `pending` 占 30~80%。

### P1-1 分类决策顺序错误

`agent_generic_flow.py` 先按**维度名称**选短名单，再加载规则正文判定。用弱信号（中文标签名）剪枝强判断（规则正文）的输入空间，是净损失。且分类发生在来源审核**之后**，标签错了凭证已冻结。

### P1-2 一票否决整个 Session

`commit_plan` 中任一 `retry_tasks` 非空即整场 `deferred`。**一条长尾候选失败 → 整个 Session 数据丢失**（且无回捞路径）。

### P1-3 主体未定即丢弃

`agent_contracts.py` 中 `subject_role=unresolved` 会阻止候选入库。但儿童对话中大量**关系信息**（"小明今天没来"）天然需要跨会话累积才能确定主语——**这正是记忆系统最该做的事，却被当废品丢弃**。

### P2-1 缺维度却扣置信度

`REVIEW` 提示词声明"未知维度不构成 pending"，但因分类在审核之后，该声明在链路中无法生效。

### P2-2 缺失反悔机制

进入 `reviewed` 即永久有效，**没有衰减、降级、失效重评**。这既是保守策略的深层原因（不能反悔 → 只能不写），也导致过时画像无法退场。

### P2-3 生产链路实际无网络重试

`agent_llm.py` 对 v2/v3 流程强制 `retries=0`，同时 `network_retries` 被列为废弃键 → **瞬时断连完全不重试**，可靠性仅靠 `stage_max_attempts` 的协议重试。

### P2-4 其他工程细节

| 问题 | 位置 | 影响 |
| --- | --- | --- |
| 按 ISO **字符串**排序，未归一化时区 | `agent_data.py` | 跨时区时 `gap-*` 会话边界可能错位 |
| 单条脏行即整用户失败 | `agent_data.py` | 无逐行隔离 |
| 失败调用也扣预算；`chars` 不含 schema 与图片 | `agent_llm.py` | `max_total_input_chars` 低估真实传输量 |
| 只有显式配置才发 `max_tokens` | `agent_llm.py` | 输出上限与预算预留不一致 |
| `bounded_history` 静默丢项不报告 | `agent_context.py` | 历史可能被无声截断 |
| `KeyError` 逃逸拆分重试 | `agent_context.py` | 升级为 Session 级失败 |
| `raise` 之后的 `append` 不可达 | `export_memory_html.py` | `index_report.html` 缺 reviewed 用户卡片 |
| 未知 role 的 schema 返回 `None` | `agent_schema.py` | 此时不下发 `json_schema`，仅 `json_object` 兜底 |

### P3 评估能力缺失

- **没有漏斗指标**：`agent_result.summarize_results` 不统计"提取了多少候选"，分阶段留存率无法自动算出（§7 的数字是手工统计的）。
- **106 维准确率从未人工标注验收**，报告 `quality` 字段自述如此。
- **存量未完成**：文档记录已提交 269 / 剩余 901 Session；存量重复不自动修复。
- **所有离线回归为 Mock**：只证明编排与门禁，不证明语义效果。

## 9. 已提出的改进方向（未实施，供评审）

> 以下为设计建议，**代码未做任何改动**，仅作后续规划输入。

### 9.1 三条不变量（地基）

1. **价值轴不得读取事实轴与可信轴的任何字段。** 值不值得长期记，只由"内容对未来有没有用"决定，与发生在哪次会话、模型多确信无关。
2. **维度是标签，不是门禁。** 数据可得性问题只在消费侧标注，不得从分类体系删除。
3. **分层存储，各自门槛。** 情景层宽进，画像层严出，派生层可撤销。

### 9.2 分层存储

| 层 | 内容 | 目标留存 | 门槛 |
| --- | --- | --- | --- |
| 情景记忆层 | 事件、经历、当次请求 | ~100%（有证据即存） | 证据成立 |
| 长期画像层 | 偏好、特征、关系、能力 | ≥15% 候选量 | 1 次明确自述 **或** 2 次独立会话 |
| 派生结论层 | 跨会话总结 | 极小 | ≥2 独立会话（现有逻辑正确） |

**核心洞见：存下来 ≠ 提升为画像。** 现在两者被合并成一个 `retention` 决策，只能在"严"和"全"间二选一。

### 9.3 置信度改分级保留

废掉 `pending`，改为连续置信度：`≥0.8` 直接入库；`0.5~0.8` 入库并标 `provisional` 进待复核；`<0.5` 入情景层存档 + 报错清单。
置信度应由**缘信号**计算（证据覆盖、跨会话重复、时间表达、冲突检测），而非模型自评。

### 9.4 维度体系重构

改为 `大类 × 领域 × 属性 × 极性强度 × 时效` 的组合编码，维度 ID 从组合生成。
剔除三类：统计量维度（`E02`/`P08-P11`/`P13`）、产品行为维度（`P05`/`P12`/`P16`）、评价型维度（`G27`/`G28`/`G29`）。
合并重叠（`G16`/`G20`/`G31`/`E13` 实为同一"偏好"）。
能力类改存**轨迹**（"X 从 A 到 B 的变化"），而非静态值。

### 9.5 门禁降为候选级

成功的候选先入库，失败的进 `pending_revision` 队列，会话标 `partial` 但**数据不丢**。

### 9.6 补评估体系（建议最先做，成本最低）

漏斗仪表盘（`extracted → source_pass → admitted → retention=memory`）、三个比率（`unclassified_rate` / `repair_rate` / `pending_rate`）、分层抽样人工评估、标签治理流程。
