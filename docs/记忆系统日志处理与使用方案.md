# 四类日志驱动的记忆系统方案

## 1. 目标与总体闭环

本方案针对定位、拍照、智能体对话、通话记录四类日志，建立可追溯、可撤回、可评估的记忆能力：

```text
原始日志 → 清洗标准事件 → 记忆候选 → 记忆确认/衰减 → 场景使用决策 → 资源检索推荐 → 反馈回流
```

原始日志不等于记忆，检索到记忆也不等于允许使用。系统需要分别回答：发生了什么、意味着什么、当前是否允许使用、应提供什么资源。

## 2. 四类日志现状与边界

| 日志 | 主要字段 | 可提供证据 | 不可直接证明 |
|---|---|---|---|
| 定位 | device_id、lat、lon、loc_type、accuracy、address、timestamp | 设备曾上报某位置 | 儿童本人到访、家庭住址、地点偏好 |
| 拍照 | picture_id、user_id、device_id、picture_url、del_flag、create_time、validity_time | 图片记录及生命周期 | 图片内容、身份、长期兴趣 |
| 对话 | dialog_id、chat_id、text、content、audio、status、source、create_time | 会话文本和媒体引用 | text/content 的角色、助手内容是否为用户事实 |
| 通话 | video_id、caller/callee、state、end_reason、时间、duration | 通话尝试、对象、状态 | 通话内容、亲属关系、关系亲密度 |

已知样例中定位精度存在较大值、对话中 text 可能为空而 content 有问候语、通话存在 rejected 和零时长。因此必须先做字段语义和枚举确认，不能让模型猜测。

## 3. 日志清洗

### 3.1 通用清洗流程

1. **导入留痕**：记录文件哈希、sheet、行号、导入批次和原始主键。
2. **类型校验**：ID 按字符串读取；时间统一解析；数值、枚举、URL 分别校验。
3. **身份绑定**：建立设备—账号—家庭—儿童映射，按事件发生时间处理换绑和共享设备。主体无法确定时，禁止写入个人长期记忆。
4. **时间统一**：确认毫秒时间戳、时区和字段含义后统一以 UTC 存储，保留原始时间。
5. **幂等去重**：优先使用业务主键；没有主键时使用主体、类型、对象、时间窗口和内容哈希组合去重。
6. **有效性校验**：检查删除标志、授权、失效时间、状态和时间先后关系。
7. **隐私最小化**：精确坐标、原始媒体 URL、联系人姓名和原始音频不默认写入提示词或长期记忆。
8. **结果分流**：记录进入 `accepted`、`degraded`、`quarantined`、`ignored` 或 `revoked`，并保留原因码，不能静默删除。

### 3.2 定位日志清洗

- 校验经纬度范围、坐标系、accuracy 单位和 loc_type 枚举。非法坐标隔离，精度不足时只保留城市或区域级信息。
- 同一设备短时间相同或极近坐标去重；结合时间、距离、精度检测跳点，异常跳点不得生成行程。
- 通过空间聚类和停留时长生成 `place_stay`，但只有跨日重复、采样充分且身份明确时才生成“常活动区域”候选。
- 原始精确坐标只放受控原始层，记忆层保留粗区域、时间段、证据数量和精度等级。
- 单次到访不能推断家庭住址、学校、喜欢该地点或儿童本人到访。

### 3.3 拍照日志清洗

- 按 picture_id 去重；确认 create_time 是否为拍摄时间，update_time 不直接算成新拍摄。
- 根据 del_flag 过滤删除记录；确认 validity_time 表示访问、展示还是数据有效期后，再决定是否撤销派生记忆。
- 校验 URL 格式和来源域。访问失败进入重试，不直接判定图片不存在。
- 授权媒体处理后，使用文件哈希去完全重复，感知哈希只标记近似图片，不把不同视角强行合并。
- 图片模糊、过暗、遮挡应降低 OCR/VLM 置信度。只有授权后识别出的文字、物体、场景才能成为候选。
- 禁止默认推断人脸身份、健康、情绪、种族或喜欢程度；“拍过”不等于“喜欢”。

### 3.4 对话日志清洗

- 首先确认 text、content、audio、content_tts_audio 分别对应用户、助手、系统还是工具，并统一为 user/assistant/system/tool 角色。
- 按 chat_id、dialog_id 和时间恢复会话顺序；文本与同一轮音频转写只保留一份提取证据。
- 清除欢迎语、系统模板、重试、空输入和无业务意义的重复内容，但保留原始记录。
- “不是”“不要”“我不想”等否定和纠正不能按短文本过滤；需结合前后轮解析。
- 区分现实陈述、引用、故事、假设和愿望。助手复述、建议或生成内容不能单独成为用户事实。
- 音频转写要记录转写版本和低可信片段；score/status 不能直接当作语义置信度。

### 3.5 通话日志清洗

- 以 video_id 去重，trace_id 用于链路关联；caller_type/callee_type 决定 ID 命名空间，设备 ID 和账号 ID 不能直接混用。
- 按 state、end_reason 区分接通、拒接、取消、超时、异常结束；未接通允许 connected_at 为空，duration=0 不自动删除。
- 校验 started_at ≤ connected_at ≤ ended_at（字段存在时），确认 duration 单位和起算点后再比对。
- 拨号、接通、结束属于同一会话阶段，统计时不能累加为三通电话。
- 高频联系人只能形成“常联系对象”候选，必须结合身份映射、重复证据和授权，不能单凭频率推断亲属或亲密关系。

## 4. 记忆提取

### 4.1 方法分工

| 方法 | 适用信息 | 示例 |
|---|---|---|
| 规则 | 明确指令、删除、状态、时间、禁推 | “不要再推荐数学” |
| 统计 | 频率、最近性、重复主题、停留聚类 | 多次主动谈同一主题 |
| LLM/语义分析 | 事实、偏好、目标、经历、否定、实体 | “我最近在学恐龙” |
| OCR/VLM | 授权图片中的文字、物体、场景 | 植物、动物、作业主题 |

### 4.2 记忆提取步骤

1. 检查主体、授权、质量状态，选择规则、统计或语义路线。
2. 输出固定结构：主体、记忆类型、谓词、对象、时间、显式/推断标记、置信度、敏感度、证据和用途。
3. 验证证据确实存在于源事件，验证文本跨度、图像区域和发言角色；不存在的证据直接拒收。
4. 对主题、地点、资源实体进行同义归一化，但不要把泛主题和具体知识点过度合并。
5. 以“主体+类型+谓词+对象+有效时段”查重，区分新增证据与同一行为的重复导入。
6. 明确表达可进入候选；统计推断和模型推断先进入 candidate，多次独立证据或用户/家长确认后再 active。
7. 高敏感、主体不确定、冲突或涉及儿童安全的候选进入确认流程。

建议记忆类型：`preference` 偏好、`interest` 阶段兴趣、`goal` 目标、`experience` 经历、`learning_state` 学习状态、`relationship` 关系、`routine` 习惯、`constraint` 禁忌、`current_state` 短期状态。

被动曝光、同会话复述、同图重复和单次跳过不能直接提高稳定兴趣。当前四类日志没有标准化测评题目和得分，不能据此生成客观学习能力。

### 4.3 冲突与生命周期

状态建议为：`candidate` 候选、`active` 可用、`disputed` 冲突、`stale` 待复核、`expired` 过期、`revoked` 撤销。

- “以前喜欢，现在不喜欢”：结束旧偏好的有效期，保留历史，不删除已发生经历。
- “刚才说错了”：建立纠正关系，撤销被纠正断言。
- 家长限制与儿童偏好分开保存，限制影响是否使用，不覆盖事实。
- 短期状态按天级衰减，兴趣按周/月复核，明确禁推持续到撤回或指定期限。
- 冲突未解决的记忆不用于肯定式话术；显式纠正优先于统计推断。

## 5. 保存结构

### 5.1 混合存储

- **关系库**：标准事件、身份绑定、记忆、证据、权限、冲突、反馈，作为唯一真源。
- **对象存储**：原始 Excel、授权图片、音频和转写，负责追溯和重处理。
- **全文索引**：会话文本、主题、地址规范词和资源标签，支持关键词和实体过滤。
- **向量索引**：记忆摘要、图片派生描述和资源描述，用于语义召回；结果必须回表核权限、版本和有效期。
- **关系边表**：主体—实体、主体—地点、主体—联系人、记忆—证据；当前规模不必直接部署图数据库。

事实、系统推断和推荐控制必须分表。点击、完成、跳过和推荐曝光不能直接覆盖用户事实。

### 5.2 标准事件结构

```json
{
  "event_id": "内部事件ID",
  "source_type": "location|photo|dialogue|call",
  "source_object_id": "源记录主键",
  "subject_id": "真实主体ID",
  "household_id": "家庭隔离域",
  "device_id": "设备ID",
  "session_id": "对话或通话会话ID",
  "event_type": "规范化行为类型",
  "occurred_at": "业务发生时间",
  "received_at": "系统接收时间",
  "payload": "按事件类型约束的内容",
  "quality_status": "accepted/degraded/quarantined",
  "consent_scope": "授权范围",
  "raw_ref": "源文件、sheet、行号或媒体引用",
  "processing_version": "处理规则版本"
}
```

### 5.3 记忆结构

```json
{
  "memory_id": "记忆ID",
  "subject_id": "主体ID",
  "memory_type": "preference|interest|goal|experience|constraint",
  "predicate": "记忆关系",
  "object": "实体或值",
  "summary": "可读摘要",
  "origin_kind": "explicit|inferred|confirmed",
  "status": "candidate|active|disputed|expired|revoked",
  "confidence": 0.0,
  "sensitivity": "low|medium|high",
  "valid_from": "生效时间",
  "valid_to": "失效时间",
  "evidence_refs": ["证据ID"],
  "usage_scope": ["允许场景"],
  "assertion_policy": "可陈述/仅选择/需确认/禁止提及",
  "extractor_version": "规则或模型版本"
}
```

证据表需保存 evidence_id、源 event_id、原文跨度/图像区域、发言角色、支持/反驳/纠正、独立证据组和提取版本，以便解释“为什么记住”。

## 6. 使用与检索

每次调用先生成 UsePlan：主体、场景、当前意图、使用目的、需要的记忆类型、时间范围、授权范围、敏感级别、资源约束和返回条数。

检索顺序：主体/家庭硬过滤 → 场景与用途 → 授权、敏感度、状态、有效期 → ID/实体/时间精确召回 → 向量语义补召回和受限关系扩展 → 回关系库验证版本、证据和冲突 → 按当前相关性、确认程度、证据质量、时效、多样性、拒绝记录和冷却期重排。

场景策略：

- **学习**：学习状态决定知识点，兴趣只决定呈现形式。当前日志不足以判断掌握度。
- **连续对话**：当前话题优先，其次是近期目标和已确认兴趣；只取少量相关记忆，不暴露完整画像。
- **主动内容推荐**：当前意图优先，禁推、年龄、安全和冷却为硬过滤条件。
- **拍照问答**：优先使用当前照片的授权标签和 OCR 结果，不用历史兴趣改写当前识别事实。
- **位置辅助**：只在授权后使用粗区域、时段和场景，不直接使用家庭精确地址。
- **家庭沟通**：仅在明确授权的提醒场景使用联系人和通话频率，默认不向儿童展示联系人详情。

`allowed`（是否允许使用）与 `score`（相关性分）必须分开；禁推、越权、安全或年龄条件不通过时，即使相关性很高也不能使用。无合格结果时返回未知，不编造记忆。

## 7. 资源推荐闭环

资源项至少包含 `resource_id/version`、`resource_type`、`topics/entities`、`skill_or_goal`、`scene`、`age_range`、`difficulty`、`language`、`duration`、`execution_entry`、`status`、`source`。

先检索允许使用的记忆，再转换为资源需求，最后检索资源。资源流程为：主题/目标召回 → 年龄、安全、授权、上下架过滤 → 禁推、冷却、已完成过滤 → 相关性和多样性排序 → 返回真实执行入口。

每次推荐记录 request_id、使用的 memory_ids、候选/最终 resource_ids、排除原因、策略版本和 exposure_id。反馈区分未展示、点击、开始、完成、跳过、拒绝、明确禁推和纠正。跳过不等于不喜欢，拒绝单条内容不等于禁用整个主题。

## 8. 评估与分期

按用户和时间建立标注集，分别评估清洗分流、主体绑定、记忆 precision/recall、证据正确率、检索 Precision@K/Recall@K、重复推荐率和跨家庭越权率。先影子运行，再灰度开放低风险场景；最终推荐必须能反查请求—记忆—证据—原始行。

| 阶段 | 交付物 |
|---|---|
| 第一期 | 字段与枚举字典、身份/时间映射、四类清洗、标准事件和幂等导入 |
| 第二期 | 对话显式偏好/目标/禁推、低风险统计兴趣、证据、冲突和生命周期 |
| 第三期 | UsePlan、关系库+全文/向量检索、权限过滤、检索评测和使用日志 |
| 第四期 | 资源目录、曝光/完成/拒绝反馈、冷却、多样性和灰度发布 |
| 后续 | 授权图片理解、位置场景、关系辅助、成本监控和规模治理 |

实施前必须确认：设备与儿童/家长/家庭映射；对话 text/content 角色及状态枚举；时间单位、时区、坐标系和 accuracy 单位；图片授权与 validity_time 含义；通话类型和联系人关系来源；可使用记忆的场景边界；资源目录和反馈接口；原始数据与派生记忆的保留、撤回、删除责任。
