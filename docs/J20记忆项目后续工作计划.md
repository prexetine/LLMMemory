# J20 记忆项目后续工作计划

> 本文是工作安排，不代表各阶段已经执行。阶段一已完成数据审计与初筛，核心名单仍需业务复核；本次补充阶段二的记忆结构设计与提取规范，不启动模型提取、媒体下载或索引建设。
>
> 上层方案：[J20核心用户记忆维度与提取存储规划](J20核心用户记忆维度与提取存储规划.md)。

## 1. 工作目标与边界

从四类 J20 日志出发，按设备确定分析主体，筛选前 100 位候选，经测试账号核查确定约 50 位核心用户。围绕产品的 106 项记忆维度完成提取、证据关联、关键词整理及三种存储表达。

工作包括：数据审计、用户筛选、维度规范、小样本试提取、核心用户批量提取、存储产物生成和质量验收。

暂不包括：在线检索接口、召回排序、记忆调用、资源推荐和线上效果实验。

已确认原则：

- 以 `device_id` 为本次用户分组依据，保留原始账号关联；不将设备等同于唯一现实儿童。
- 主排名采用有效用户对话轮数；并列时依次比较对话活跃天数、有效拍照记录数、接通通话数，最后按设备 ID 保证排序可复现。
- 定位自动上报量不参与活跃排名。
- 先确定核心用户，再分批处理相关图片，不下载全部用户图片。
- 一份带证据和关键词的权威记忆，派生向量、关键词索引及 Wiki 目录。
- 全部提取指全部范围内的记录有处理结果、全部维度有覆盖状态，不要求每个维度都有确定结论。

## 3. 阶段一：数据审计与核心用户筛选

### 工作内容

1. 登记四类日志和产品维度文件的实际路径、版本、文件哈希、工作表及字段。
2. 流式扫描全部工作表，统计数据量、时间范围、设备分布、空值、重复、删除和异常情况；大文件不一次性全部载入内存。
3. 确认对话字段角色、会话标识粒度、时间单位、状态枚举及通话参与方类型。未确认项保留问题清单，不按猜测计数。
4. 定义有效用户对话轮数，排除重复、已删除、纯系统模板和仅助手发言；短句否定或纠正不能按长度直接排除。
5. 按已确认口径生成前100位设备候选，保留各项原始统计与排名依据。
6. 检查测试指令、重复文本、异常密集调用及系统素材嫌疑，生成复核清单；不因高活跃或单个异常直接排除。
7. 经人工复核后按排名选取约50位核心用户，保留排除、待确认和候补状态。不足50位时如实说明，不凑数。

### 交付物

- 数据审计报告：数量、时间、字段问题、来源覆盖与处理口径。
- 前100位候选表：排名、设备标识、有效对话轮数、活跃天数、拍照和通话统计。
- 测试嫌疑与复核表：证据、判断、排除或保留理由。
- 核心用户名单：入选依据、可用来源及异常标记。

### 完成标准

排名可复现，输入与清洗分流数量可对账；每个排除决定有依据；身份异常和字段不确定性没有被静默忽略。

本阶段不下载图片、不执行全量语义提取。图片有效数为元数据检查后的统计，不能直接当作真实用户照片数。

## 4. 阶段二：记忆结构设计、106项维度与提取规范

本阶段先回答“提取结果长什么样、如何关联和更新”，再回答“每个维度怎么提取”。不能只有维度清单和提示词，没有统一的记忆数据结构。以下为设计基线，完整字段字典、106项映射及样例需在本阶段评审定稿。

### 4.1 工作顺序与边界

1. **设计记忆结构**：明确事件、原子记忆、证据、维度、关键词和覆盖结果的对象、字段与关联。
2. **设计维度映射**：将产品106项维度逐项映射到上述结构，标明来源、提取方法及不支持的情况。
3. **设计提取规范**：定义提取输入、输出、证据要求、归并、冲突、纠正和入库校验。
4. **设计存储表达约定**：明确同一记忆如何派生向量、关键词与Wiki，不在本阶段建设索引或检索接口。
5. **评审样例**：用人工构造的正反例检查结构能否表达事实、未知、否定、变化和探索发现，再进入阶段三真实数据试提取。

### 4.2 记忆结构：对象与关系

采用“结构化权威数据＋三种派生表达”的方案。结构化数据计划落入SQLite，支持JSONL导出；向量、关键词索引与Wiki不是三份独立事实库。

| 对象 | 标识与主要内容 | 含义与作用 |
|---|---|---|
| 分析主体 | `device_id`、账号别名、主体归属状态 | 本批按设备隔离数据；不能据此断言设备只属于一个儿童 |
| 事件 | `event_id`、设备、来源类型、发生时间、原始行定位、处理状态 | 表达“发生或记录了什么”；原始行定位至少含文件、工作表、行号，保留原始记录ID（如有） |
| 维度 | `dimension_id`、产品路径、定义、来源引用、规范版本 | 表达产品要观察什么；产品路径保留通用、蛋宝必需、探索三层分类及下级目录 |
| 原子记忆 | `memory_id`、归属主体、结论、主维度、性质、时间与状态 | 一条只表达一个可独立验证、纠正或失效的结论，不以一段用户画像代替多条记忆 |
| 证据关联 | 记忆ID及版本、事件ID、证据位置、证据作用、提取依据 | 连接结论与源记录；证据作用区分支持、反驳、上下文，助手回复不能冒充用户陈述 |
| 维度关联 | 记忆ID、维度ID、主/辅关联 | 一个事实可覆盖多个维度，但不为每个维度复制一份事实；保留唯一主维度用于目录归档 |
| 关键词关联 | 记忆ID、词组类型、规范词、原词 | 支持维度词、实体词、行为词和场景词；规范词用于统一表达，原词用于复核 |
| 覆盖结果 | 设备、维度、处理批次、检查范围、状态、关联记忆ID、原因 | 回答该用户该维度是否检查、为什么没有结果；没有记忆也必须有覆盖状态 |
| 派生表达记录 | 记忆ID、记忆版本、表达类型、生成版本、同步状态 | 跟踪向量、关键词与Wiki是否已同步，避免记忆更新后仍留下旧表达 |

关联原则：一个设备有多个事件和记忆；事件与记忆通过证据形成多对多关系；记忆与维度、关键词也可多对多关联。所有关联都校验设备归属，禁止跨设备误连。设备内确需区分本人、家长、朋友等实体时增加局部实体标识；不凭同名或相似文本跨用户合并。

事件不是记忆：一次拍照、一次通话、一句询问可以是事件，但未必形成稳定结论。记忆必须说明由哪些事件、通过什么方法得出；统计结果必须能回查统计范围，不能只有一句模型摘要。

### 4.3 原子记忆字段设计

| 字段 | 含义及约束 |
|---|---|
| `memory_id`、`version` | 稳定记忆编号及递增版本；编号不直接使用会随措辞改变的摘要，修改后保留历史 |
| `device_id`、`subject_ref` | 前者确定数据隔离范围，后者说明结论谈论谁；主体不明时标待确认，不自动归为设备使用者 |
| `dimension_id`、`related_dimension_ids` | 主维度与辅助维度编号；必须引用正式维度字典，不允许模型临时发明产品维度 |
| `memory_type` | 结论类别，如资料、偏好、经历、约定、行为模式、关系；与产品维度分开，不能相互替代 |
| `claim`、`claim_slots` | 可读的一句话结论及结构化的主体、关系/行为、对象、限定条件；用于核验、去重和变化判断 |
| `result_kind` | 明确表述、统计观测、推断候选或探索假设；明确表述只代表用户这样说过，不等于已核实的客观事实 |
| `polarity`、`modality` | 肯定/否定，以及现实陈述、愿望、计划、假设等语气；“想学游泳”不能写成“会游泳” |
| `keywords` | 分组保存维度词、实体词、行为词、场景词，每项带规范词和原词；否定、时间另存字段，不仅靠关键词体现 |
| `time_scope` | 分开记录证据观测起止、结论适用起止、时间精度及是否推定；未知时间留空，不虚构永久有效 |
| `evidence_refs` | 证据关联引用；文本定位到话轮/片段，媒体定位到媒体记录及识别结果，统计定位到事件集合或可复算条件 |
| `confidence_basis` | 保存明确性、独立证据量、跨时间重复、反例及限制；模型自评分不能直接当成真实概率 |
| `status`、`review_state` | 生命周期状态如候选、有效、冲突、被替代、撤回；复核状态另记未复核、通过、驳回，避免混为一谈 |
| `supersedes_id`、`conflict_refs` | 指向被替代的旧记忆及冲突对象；更正与时间变化不能简单覆盖证据或删除历史 |
| `sensitivity`、`retention_policy` | 敏感等级与保留/到期处理规则；用于约束摘要、媒体及派生表达中的暴露范围 |
| `extractor_version`、`schema_version`、`batch_id` | 提取规则/模型版本、结构版本及处理批次，便于复现、修订和定位错误 |
| `created_at`、`updated_at` | 系统创建和更新时间，不与事件发生时间混用 |

实际入库时，证据、维度关联和关键词可使用独立关联表；JSONL导出可嵌套展示，但含义与标识保持一致。字段字典还须逐项补齐类型、必填性、允许值、空值含义和示例；未知用空值及原因表达，不能用0或否定代替。

### 4.4 产品106项维度映射

保留通用46项、蛋宝必需16项、探索44项，逐项建立稳定编号并引用产品原始条目。对原产品方案中的场景关联，只登记该维度服务的产品目的及可观察依据，不在本阶段实现记忆调用或推荐。

每项映射包含：维度编号与产品路径、定义与边界、可用来源、对应记忆类别、提取路线、证据门槛、关键词规则、时间属性、正反例、敏感性、缺失处理。来源说明从哪里找；提取路线区分规则、统计、语义与视觉；证据门槛限制结论强度；正反例说明何时应提取、何时不应提取。

覆盖状态至少区分：有结果、已检查无证据、证据不足、冲突、来源缺失、待媒体处理、受限未处理、处理失败。已检查无证据只对记录的检查范围成立，不能写成“用户不存在该特征”；失败也不能归为无证据。

### 4.5 提取规范：从事件到记忆

**输入与角色约束**：每批输入携带设备、事件标识、时间、来源、说话角色及适用维度定义。已确认对话 `text` 为用户输入、`content` 为助手回复，`status=0`、`del_flag=0` 为正常未删除记录。助手内容仅用于理解上下文，不能单独支持用户事实；故事、角色扮演、引用他人话语须与本人自述区分。

| 来源 | 提取方法 | 不能越过的证据边界 |
|---|---|---|
| 对话 | 语义分析结合明确规则，保留必要上下文，识别主体、否定、意愿及纠正 | 一次提问不直接形成稳定兴趣；自述能力不冒充测评结论 |
| 定位 | 时间与空间规则、停留及重复模式统计 | 设备出现地点不直接等于住所、学校或本人实际活动；推断需独立支持 |
| 拍照 | 先检查元数据，再按授权进行视觉/OCR与上下文分析 | 未识别的图片只能保留拍照事件；画面中物品不自动等于所有物或兴趣 |
| 通话 | 状态、方向、频次及时间窗口统计 | 接通次数不等于亲密程度，联系人不等于亲属；没有通话内容时不能提取谈话事实 |

**输出约定**：提取器只产出候选结论、主体、维度、性质、关键词、时间、证据引用及限制。系统统一分配记忆ID、校验证据并执行归并；模型不能自行宣布已入库，也不能虚构源事件ID。统计候选必须保存指标定义、窗口、计数、分母（如适用）、去重口径及来源集合。

**入库流程**：候选输出 → 结构校验 → 主体与证据校验 → 去重及冲突检查 → 状态判定 → 写入记忆与证据 → 更新维度覆盖。结构校验拒绝未定义字段、非法枚举和未知维度；证据校验检查引用存在、设备一致、原文是否支持结论。失败记录保留原因，不能悄悄丢弃。

**归并与更新规则**：

- 同一事件重复导入、同轮复述、同图重复不增加独立证据量；同义表达只有主体、含义、时间和限定条件兼容才可合并。
- 新证据支持同一结论时追加证据并更新版本；不能只凭向量相似就合并不同事实。
- 同时间范围的矛盾先标冲突；明确纠正保留替代关系；不同时间的偏好变化保留各自适用范围。
- 推断候选和探索假设单独标记，不自动升级为有效事实；探索发现记录支持证据、反例、其他解释和验证条件。
- 源证据撤回后重算支持情况；必要时降级或撤回记忆，并使三种派生表达失效或等待重建。

**结构验证样例（虚构，不代表本批用户结论）**：两个独立日期的“我喜欢恐龙”事件可共同支持一条“用户自述喜欢恐龙”的偏好记忆，分别关联证据并保存关键词“恐龙”；同一事件还可能支持其他结论，不必复制事件。之后出现“现在不喜欢恐龙了”，应保留旧偏好的历史范围和新否定记忆，建立变化关系，而不是把旧记录直接抹掉。“给我讲恐龙故事”只能支持一次内容请求，单独不足以证明稳定偏好。

### 4.6 三种存储表达的设计约定

阶段二定义表达结构，阶段五实施生成与同步：

- 向量：一条原子记忆及必要上下文对应可追溯的向量记录，带记忆ID、版本、设备、维度、状态、模型版本。
- 关键词：建立规范词到记忆ID的关联，保留原词与词组类型；事实含义仍以原子记忆的否定、时间和状态为准。
- Wiki：按“设备用户 → 产品层级 → 类别 → 维度 → 记忆条目”组织目录；条目引用同一记忆ID、证据及时间，跨维度只增加引用，不复制结论。

三种表达均从已校验的权威记忆生成。有效记忆与待验证候选分区或明确标记；更新、撤回与删除按记忆ID及版本传播。此处不设计召回、排序或业务调用策略。

### 4.7 交付物与完成标准

交付内容集中到现有《J20核心用户记忆维度与提取存储规划》中，不按每个小任务新增文档：

1. 记忆结构说明：对象关联、完整字段字典、生命周期及三种表达约定。
2. 106项维度映射：逐项来源、方法、证据门槛、关键词与缺口。
3. 提取规范：输入输出结构、校验、归并、冲突、纠正和覆盖规则。
4. 验收样例：明确表述、否定、愿望、主体不明、多事件归并、时间变化、无证据及处理失败等正反例。

完成标准：106项均有处理方法或明确数据缺口；每种候选都能按统一结构表达并追溯证据；每个字段含义、类型及约束清楚；归并、纠正和撤回可按规则判断；三种表达能引用同一记忆而不产生三套事实。生日等资料直读项缺少来源时标为缺失，不为了填满维度制造结论。上述交付需完成并通过评审，不能以本工作计划的补充代替阶段二验收。

## 5. 阶段三：5位用户小样本试提取

### 工作内容

1. 从核心名单中选择5位数据特征不同的用户，覆盖对话丰富、图片丰富、多来源完整及数据稀疏或异常等情况；若样本不具备某类特征则记录缺口。
2. 对这5位用户范围内的记录执行清洗、标准化、分段提取、证据校验、跨会话归并及维度补漏。
3. 图片先过滤系统素材和重复记录，再受限、分批获取及识别，记录失败和待处理状态。
4. 产出结构化记忆、关键词和Wiki样例；验证向量表达的粒度，不先建设在线查询能力。
5. 人工核查事实、主体、角色、否定、冲突、关键词及探索推断，记录错误类型和修正策略。
6. 统计处理时长、模型调用量、媒体容量及失败情况，为后续批量规模和费用提供依据。

### 交付物

- 5位用户记忆样例及证据链。
- 5×106项维度覆盖结果。
- 图片处理清单与缺失说明。
- 错误分析、规范修订及批量成本预估。

### 完成标准

产品方能理解并确认记忆粒度、关键词和Wiki组织方式；主要错误已有修正措施；未处理来源明确列出。调用模型前确认服务环境、预算、数据处理边界及媒体保留期限。

## 6. 阶段四：约50位核心用户批量提取

### 工作内容

1. 按设备和会话/时间段分批处理，建立任务清单、失败重试、版本记录和断点续跑。
2. 对话走语义路线，定位与通话频率走规则统计路线，图片走视觉/OCR路线；不把所有记录都交给大模型。
3. 复用已校验的小样本结果；规范或模型版本变化时明确重处理范围，避免混用不可比较版本。
4. 合并同主题证据、保留冲突和时间变化，防止重复导入、同轮复述、同图重复计权。
5. 执行106项维度补漏，回查源事件，不只重读第一次摘要。
6. 形成探索发现：共同作品、专属互动、约定兑现、跨会话续接，以及分享—拍照—通话的重复组合等。

### 交付物

- 核心用户记忆全集与证据关联。
- 用户×维度覆盖矩阵。
- 媒体、失败任务、待确认项清单。
- 独立的探索发现报告，包含证据、反例、其他解释和候选性质。

### 完成标准

每条源记录有处理状态，每条记忆有可定位证据。没有静默跳过的任务；未解析媒体明确标记未完成，不伪装成无相关记忆。时间关联不写成因果，行为模式不升级为心理诊断。

## 7. 阶段五：三种存储表达

### 工作内容

1. 以SQLite中的结构化记忆及证据为权威源，提供JSONL导出。
2. 每条记忆分配稳定记忆ID和版本，保存主体、维度、原子结论、关键词、时间、状态、结果性质及证据。
3. 从同一源生成向量表达、关键词关联和Wiki目录，禁止三套独立提取各自产生事实。
4. 验证更新、纠正及撤销如何同步到三种表达，失败任务保留待同步状态。

| 产物 | 保存内容 | 约束 |
|---|---|---|
| 向量表达 | 原子记忆文本、必要上下文、向量、模型版本、记忆ID | 不将整份画像压成一个向量 |
| 关键词关联 | 维度词、实体词、行为词、场景词、规范词与原词 | 否定和时间另存结构化限定，不只靠词表达结论 |
| Wiki | 用户首页、产品维度目录、记忆条目、证据、时间线、缺失说明 | 目录引用同一权威记忆，不创造额外事实 |

### 交付物与完成标准

交付结构化库及导出、向量产物、关键词关联、每用户Wiki和一致性报告。三种表达的记忆ID、版本、状态与证据一致；缺失维度保留说明，敏感原始信息不无必要地进入摘要和目录。

本阶段不实现搜索API、混合召回、排序或资源推荐。

## 8. 阶段六：质量验收与总结

### 检查内容

- 全部核心用户纳入人工抽查，重点检查身份、关系、能力与探索推断。
- 50位用户对应5,300个维度覆盖单元；按实际入选人数计算，不以填满结论作为质量指标。
- 在独立标注样本中评估提取正确性与遗漏，分别报告明确事实、统计和探索候选的质量。
- 测试重复导入、助手自述、故事和假设、否定纠正、共享设备、图片重复、源数据缺失等反例。
- 验证从记忆能追溯到证据和源行；三种存储表达没有串用户、过时版本或断开的证据引用。
- 验证纠正、撤回及删除依赖更新，不能仅改Wiki而留下旧向量或关键词关联。

### 交付物

质量报告、未完成与失败清单、产品维度优化建议、后续扩展建议。报告明确可确认事实与待验证发现，不承诺模型零遗漏。

## 9. 两次评审与协作分工

### 评审一：名单、记忆结构与提取规范

在阶段1和阶段2结束时，确认核心名单、测试账号判定、记忆结构与字段字典、证据关联、维度定义、提取边界、更新规则和数据缺口。通过后再进入小样本媒体处理和模型提取。

### 评审二：5位样例与批量条件

确认记忆粒度、关键词、Wiki样式、主要错误修正及预算。通过后再扩大到约50位用户，避免批量返工。

建议分工：数据/业务负责人解释字段和测试账号；产品负责人确认维度及样例；实施方负责处理、证据、存储和质量报告。具体人员与排期另行确认，不在当前文档中虚设负责人或工期。

## 10. 紧接着要做的工作

阶段一审计与初筛成果已保留，测试账号及核心名单仍需业务复核。下一步推进阶段二，按以下顺序整理到现有规划文档：

1. 先定记忆结构：对象关系、字段、关键词、证据、时间与更新规则。
2. 再补106项维度映射：直接提取、统计归纳、媒体依赖和当前不支持的维度。
3. 最后定提取规范与验收样例：输入输出、校验、归并和覆盖状态；完成评审后才进入5位用户试提取。

这一步不下载图片、不执行批量模型提取。实际模型服务、调用预算、授权媒体处理及保留期限在小样本阶段前确认；真实工期依据全量审计和小样本性能评估后制定。
