# ToyMemory 记忆-内容-推荐整体方案

> 版本：V0.2 日期：2026-09-07

## 一、要解决的问题

### 1.1 背景：内容消费是设备的留存主线，但它现在不认人

设备交付到家庭之后，孩子每天真正在用的是内容——点播故事、听儿歌、听新闻、和智能体聊天。内容消费的频次和时长，决定这台设备是"每天用的"还是"进抽屉的"。

但现在的内容分发对所有孩子是同一套逻辑：热门、榜单、分类目录。三岁和六岁、爱恐龙和爱小动物的孩子，打开看到的是同一批东西。设备记得住孩子的名字，却不记得他喜欢什么。

### 1.2 儿童语音场景让推荐不是加分项，而是唯一的导航

| **场景约束** | **带来的后果** |
| --- | --- |
| 没有屏幕可翻 | 孩子无法浏览目录、无法比较，只能听系统给的那几条 |
| 一次交互只能说 2～3 条 | 内容库上万条，每次曝光窗口极小，选错就等于没推 |
| 孩子说不清需求 | "我要听那个恐龙的"是典型表达，指望精确检索不现实 |
| 兴趣变化快 | 这个月恐龙、下个月消防车，静态画像很快过期 |

在有屏产品里推荐是"帮你少翻两页"，在语音产品里推荐就是导航本身：推得准不准，直接等于孩子能不能找到想听的东西。

### 1.3 三块数据各自为政

- **记忆有产出、没出口**：平台已能从对话抽取"喜欢恐龙"这类记忆，家长审核确认后却没有任何下游动作。更麻烦的是，家长审核是要花时间的劳动，确认完看不到孩子那边有任何变化，下次就不愿意再审——记忆质量会跟着衰减；

- **内容有标签、不认人**：内容库标签体系完整（实体、体裁、能力、语言都有），但标签从来没有和"这个孩子是谁"发生关系，再细的标签也只是分类目录；

- **行为最真实、却在流失**：孩子听了什么、听没听完、拒绝了什么，这是比对话更硬的偏好信号，目前既没有采集，也没有沉淀成任何可复用的东西。

### 1.4 为什么不能照搬通用推荐做法

| **通用做法** | **在儿童场景的问题** |
| --- | --- |
| 协同过滤"听了还听" | 单家庭样本极稀疏；且会把所有孩子推向同质化热门内容，越推越像 |
| 埋点优化点击率 | 系统闲置推送产生的收听会被当作偏好，形成"系统推什么、孩子就'喜欢'什么"的自我循环 |
| 纯偏好最大化 | 爱恐龙就一路只推恐龙；家长要的是成长价值，不是单一题材喂到饱 |
| 端到端让模型决定推什么 | 敏感内容（害怕的事、秘密、家庭事件）一旦推错，代价远高于推得不准；且事后解释不了"为什么给我孩子推这个" |

结论：这个场景需要的不是更强的预测模型，而是**一份可解释、可审核、家长认账的孩子画像**，加上**确定性的召回与过滤规则**。

### 1.5 双重用户：孩子要愿意听，家长要放心

| **角色** | **真正关心的** | **方案的回应** |
| --- | --- | --- |
| 孩子 | 想听的东西能出现，不被反复推不想听的 | 记忆驱动召回；拒绝和"不再推荐"立即生效 |
| 家长 | 我孩子的数据怎么用、为什么推这个、我能不能管 | 记忆状态由家长掌握；每条记忆可溯源；每次推荐留依据 |

家长是决定这台设备继续用下去的人。数据可查、边界清楚、随时可关，不是附加要求，是产品能不能活的前提。

### 1.6 本方案要达到的

1. 记忆有出口——家长确认的每条记忆都能变成孩子听到的内容；

2. 内容认人——同一批内容对不同孩子给出不同的召回结果；

3. 行为有沉淀——收听和反馈回流成记忆，形成越用越准的闭环；

4. 全程可解释——任何一次推荐都答得出"依据哪条记忆、家长是否确认过"。

一句话：**记住孩子 → 匹配内容 → 生成推荐 → 孩子的反应流回记忆，越用越懂孩子。**

## 二、整体流程

```text
① 采集                ② 沉淀为记忆              ③ 召回                ④ 输出与反馈
对话导入 ────────→  抽取记忆（家长审核）  ┐
                                        ├→  记忆实体 ∩ 内容标签  →  推荐候选（带依据）
设备端上报行为事件 →  行为回流为记忆信号   ┘    （黑名单/状态/         → 智能体生成话术
（点播/新闻收听、      （生成候选/调置信度/       年龄过滤）           → 孩子接受/拒绝
  推荐反馈）             进黑名单）                                          │
        ↑                                                                    │
        └────────────────── 反馈作为新的行为事件再次进入 ① ←──────────────────┘
```

记忆是整条链路的中心：对话和行为是它的两条生产线，推荐是它的消费出口，反馈再回来滋养它。

三条资产边界：

| **模块** | **权威归属** | **平台持有什么** |
| --- | --- | --- |
| 记忆 | 本平台 | 核心资产：记忆、证据、实体、状态 |
| 内容库 | 内容平台 | 只在查询时检索，不复制数据（当前演示环境用导出快照代替） |
| 推荐话术 | 各智能体 | 平台输出"推荐什么+为什么"，设备端负责怎么说 |

## 三、记忆体系：平台的核心资产

### 3.1 记什么：五类记忆

ToyMemory 的通用个人记忆不只记录“喜欢什么”，还需要回答五个问题：

1. **这个人是谁、和谁有关、平时是什么样；**

2. **这个人最近正在做什么、关注什么；**

3. **这个人经历过什么；**

4. **这个人稳定表现出的能力是什么；**

5. **孩子当前有哪些成长能力表现。**

因此，通用个人记忆划分为五类：

| **分组** | **内容** | **对象** | **在产品中的作用** |
| --- | --- | --- | --- |
| 人物画像 | 基本信息、身份角色、偏好、关系、拓展、习惯、行为风格、交互偏好 | 成人、孩子 | 理解“这个人是谁、喜欢什么、通常怎么做、希望产品怎么服务” |
| 动态状态 | 近期状态、近期关注、当前任务/项目、计划与目标 | 成人、孩子 | 承接当前上下文，避免把短期事情误当长期画像 |
| 用户经历 | 地点、技能、成就、重要事件 | 成人、孩子 | 承接真实发生过的经历，支持后续自然回忆和内容推荐 |
| 能力图谱 | 知识、语言、逻辑、创作和探索表现 | 成人、孩子 | 调难度、选题材深浅、理解稳定能力表现 |
| 幼儿成长能力 | 12 个幼儿成长维度的能力观察 | 孩子 | 能力类内容的路由（安全、情绪、科学等） |

五类展开后的维度：

| **分组** | **一级维度** | **二级维度** | **示例** |
| --- | --- | --- | --- |
| 人物画像 | 基本信息 | 昵称、性别、生日、年龄；孩子另有年级 | 小名“乐乐”；6岁；一年级 |
|  | 身份与角色 | 职业、家庭角色、学校角色、长期承担的角色 | 爸爸；产品经理；班级小组长 |
|  | 偏好属性 | 喜欢的、讨厌的、害怕的、持续关注、愿望、秘密 | 最喜欢大熊猫；对恐龙持续追问；害怕打针 |
|  | 社会关系 | 家人、老师、朋友、同学、宠物、学校、兴趣班 | 好朋友叫胖胖；家里有小狗小白 |
|  | 拓展属性 | 已拥有的物品、会做的事情、不擅长的事情等客观事实 | 会拼乐高；有一辆滑板车 |
|  | 行为习惯 | 作息、饮食、出行、运动、学习等重复发生的习惯 | 通常 21:20 睡觉；周末经常骑车 |
|  | 行为风格 | 做事、沟通、决策、任务处理上的稳定模式 | 遇到问题习惯先自己动手尝试；复杂事情更喜欢面对面沟通 |
|  | 交互与服务偏好 | 回答语言、表达方式、称呼、主动性、提醒、推荐、交互方式等 | 偏好中文回答；希望先给结论；晚上不主动推荐 |
| 动态状态 | 近期状态 | 最近一段时间正在发生、持续但非长期身份的信息 | 最近正在准备比赛；近期在搬家 |
|  | 近期关注 | 当前频繁关注，但尚不足以沉淀成长期兴趣的主题 | 最近频繁关注机器人比赛 |
|  | 当前任务/项目 | 正在推进、通常有明确结束节点的事项 | 正在准备学校科技节作品 |
|  | 计划与目标 | 用户明确表达、未来希望完成的事项 | 暑假想学会游泳；准备参加英语比赛 |
| 用户经历 | 去过的地方 | 本地地点、旅行地点 | 第一次看大海 |
|  | 学习的技能 | 运动、艺术、课程 | 学会骑自行车 |
|  | 取得的成就 | 获奖、比赛、成绩、第一次完成 | 幼儿园表演得了小红花 |
|  | 经历的事件 | 难忘、开心、交友、表演、礼物、美食等真实事件 | 生日收到恐龙玩具 |
| 能力图谱 | 8 个维度 | 认识的世界、语言成长、逻辑思维、故事与创作、情绪与表达、人文启蒙、探索与观察、兴趣与探索 | 能从 1 数到 20；会背《静夜思》 |
| 幼儿成长能力 | 12 个维度 | 情绪管理、表达交流、社会适应、文明语言、生活卫生习惯、自理能力、安全认知与保护、科学探究、数学认知、表现与创造、人际交往、感受与欣赏 | 会说“我有点难过”；知道过马路看红绿灯 |

#### 3.1.1 各类记忆的边界

| **类型** | **核心问题** | **时间属性** | **典型例子** |
| --- | --- | --- | --- |
| 人物画像 | 这个人长期是什么样 | 中长期 | 喜欢恐龙；通常早睡；偏好中文回答 |
| 动态状态 | 这个人最近在做什么 | 短期/阶段性 | 最近准备比赛；正在搬家 |
| 用户经历 | 这个人已经经历过什么 | 长期历史事实 | 去过海边；参加过比赛 |
| 能力图谱 | 这个人稳定会什么、表现怎样 | 中长期、需持续证据 | 能进行简单规律推理 |
| 幼儿成长能力 | 孩子成长能力目前表现怎样 | 持续更新 | 知道过马路看红绿灯 |

需要特别区分：

- **行为习惯 ≠ 行为风格**：前者是“经常做什么”，后者是“通常怎么做事情”；

- **偏好属性 ≠ 交互与服务偏好**：前者是“喜欢什么内容/事物”，后者是“希望产品怎么对待我”；

- **动态状态 ≠ 用户经历**：前者描述“现在正在发生”，后者描述“已经真实发生过”；

- **近期关注 ≠ 长期兴趣**：短期频繁关注不自动升级为长期兴趣，需要持续证据。

#### 3.1.2 记忆入选原则

不同维度不能统一用一套门槛：

- **人物画像**：应能稳定描述这个人。普通闲聊和一次性知识提问不形成长期画像；

- **基本信息/身份角色**：优先使用家庭成员资料、账号档案等权威来源；

- **偏好、行为习惯、行为风格**：模型推断必须有重复或跨场景证据，不能由一次行为直接下结论；

- **交互与服务偏好**：用户明确说出的要求可直接生效；若由行为推断，则需要重复证据；

- **动态状态**：允许由一次明确表达形成，但必须带时间属性，并随时间更新、结束或失效；

- **用户经历**：必须真实发生过，计划中的事情不能提前写成经历；

- **能力图谱**：只记录可稳定反映的能力表现，不因为聊到某个知识主题就记一条；

- **幼儿成长能力**：以可观察行为和持续表现为依据，避免用一次行为直接给孩子贴长期标签。

### 3.2 记忆从哪来：两条生产线

**生产线一：对话抽取（已有）**

设备对话导入后自动抽取候选记忆。质量规则从严：

- 对人物画像，主要抽取稳定事实、偏好、关系、习惯、行为风格和交互偏好；

- 对动态状态，可以记录用户明确表达的近期事项、关注、任务和计划，但必须保留时间信息，不自动沉淀成长期画像；

- 普通闲聊和一次性知识提问不形成长期个人记忆；

- 一段对话只归入最合适的一个维度，不跨分类重复生成；

- 每条记忆必须挂着直接对应的**原始对话证据**，不能拿无关对话拼凑；

- 家人说的经历和状态只归属对应家人，孩子与成人的数据严格隔离。

**生产线二：行为回流（本方案新增）**

收听和反馈行为聚合成记忆信号：反复完整收听某类内容 → 生成"喜欢××"候选记忆，证据就是那几次收听记录。两条生产线汇入同一个审核队列，且**同一份证据只算一次**——已走对话抽取的内容不在行为管道重复计分。

### 3.3 每条记忆长什么样

| **要素** | **说明** | **例** |
| --- | --- | --- |
| 标题与摘要 | 一句话事实 + 简要归纳 | “对恐龙持续感兴趣” |
| 维度 | 归属哪个分组哪个维度 | 人物画像-偏好属性 |
| 实体 | 从记忆抽出的具体对象，召回或关联的钥匙 | 恐龙、霸王龙 |
| 状态 | 生命周期位置（见 3.4） | 待确认 |
| 置信度 | 0～100，证据越多越高 | 65 |
| 时间属性 | 首次形成、最近证据、有效期/阶段等 | 2026-09-01 起；最近证据 2026-09-07 |
| 证据 | 直接支撑的原始对话或行为记录，可回溯 | “8-25 完整收听《好饿的小恐龙》” |
| 来源 | 哪台设备、什么交互方式、哪个智能体 | 阿尔法蛋·蛋宝 / 语音 / 科普蛋 |

每条记忆都回答得了"你怎么知道的"——证据可查、来源可溯，这是家长信任的基础。

### 3.4 记忆的生命周期：家长始终握着方向盘

| **状态** | **含义** | **家长可做的操作** |
| --- | --- | --- |
| 待确认 | 系统抽取、有价值但存在关键疑点 | 确认保存 / 忽略 |
| 已确认 | 家长确认，进入可用记忆库 | 停止使用 / 删除 |
| 继续观察 | 证据不足，先不打扰家长 | 系统自动积累证据，够了再升级 |
| 冲突 | 与已有记忆矛盾（如两个"最喜欢"） | 二选一确认 |
| 已忽略 | 家长选择暂不使用，数据保留 | 恢复 / 永久删除 |

三条治理约束：

1. **打扰有上限**：每个家庭每周新增待确认不超过 3 条，只把真正需要人判断的疑点交给家长；

2. **忽略可逆、删除彻底**：忽略保留数据随时恢复；删除需二次确认，连证据、调用记录、图谱连线一并清除；

3. **算法不越权**：任何行为信号、任何模型升级都不能替家长把"待确认"变成"已确认"。

动态状态在上述审核状态之外，还需要单独管理**时效状态**：

- 有明确结束时间的任务/计划，到期后不再作为当前上下文使用；

- 用户明确说“已经完成/结束”，立即结束当前状态；

- 长时间没有新证据的近期状态进入失效或归档，不继续影响推荐；

- 有长期价值且真实完成的事件，可以从“动态状态”转为“用户经历”，但不能自动把未完成计划写成经历。

### 3.5 记忆怎么被使用

状态决定用法，一条待确认的记忆和一条已确认的记忆，说出来的话不一样：

| **记忆状态** | **推荐话术** |
| --- | --- |
| 已确认 | 自然承接："你喜欢恐龙，要听《霸王龙吃饭记》吗？" |
| 待确认 | 只能询问式："上次你好像对海豚感兴趣，想听听吗？"（禁止断言"你喜欢海豚"） |
| 观察/冲突/忽略 | 一律不进推荐 |

敏感记忆另有硬约束：秘密类全场景禁用；恐惧、情绪、家庭敏感事件不做主动推荐，只在孩子自己提起时跟进；使用朋友真名须家长开关允许。

每次推荐使用了哪条记忆都留有调用记录——家长能看到"为什么给我孩子推这个"。

新增维度的使用边界：

| **维度** | **主要使用方式** | **不应直接用于** |
| --- | --- | --- |
| 身份与角色 | 称呼、上下文承接、适配角色相关内容 | 仅凭角色推断兴趣或能力 |
| 行为风格 | 调整交互过程，例如更直接或更步骤化地协助 | 给用户贴人格标签 |
| 交互与服务偏好 | 控制语言、表达长度、主动性、提醒和推荐方式 | 改变事实答案或突破安全规则 |
| 近期状态 | 承接“最近正在做什么”，提高当前对话相关性 | 长期画像和长期兴趣的直接依据 |
| 近期关注 | 作为短期排序、探索信号 | 未经持续证据直接写成“长期喜欢” |
| 当前任务/计划 | 在合适时机承接进度或相关内容 | 任务结束后持续主动提及 |

## 四、统一标签语言

记忆和内容能匹配的前提是说同一种语言。内容库的标签是混合词表（实体、体裁、能力、语言混在一起），入库时自动拆解为四类：

| **类型** | **例** | **用途** |
| --- | --- | --- |
| 实体 | 恐龙、霸王龙、幼儿园、消防车 | 与记忆实体直接匹配，召回主键 |
| 能力维度 | 安全自护、社交能力、语言能力 | 对应 12 项成长能力，能力类内容的路由 |
| 体裁归类 | 故事/绘本/冒险→故事类；科普/知识→知识类；儿歌→音乐类 | 决定归哪个智能体推 |
| 元数据 | 中文、中国、欧美 | 语言地域，不参与召回 |

配套两条实体规则：**同义归一**（大恐龙→恐龙）；**层级展开**（查"恐龙"自动包含"霸王龙"）。

已用真实内容库数据验证：恐龙主题切片 1461 条、35 个标签全部完成映射，未识别的新标签自动按实体兜底并提示运营补充。

## 五、行为采集

设备端上报行为事件，六种类型、三种触发方式：

| **事件** | **含义** | **信号方向** |
| --- | --- | --- |
| 完整收听 | 听完一条内容（含播放进度≥90%） | 正 |
| 播放 | 开始播放 | 按进度判定 |
| 跳过 | 中途退出 | 过半后跳过算弱负信号 |
| 接受推荐 | 对话内接受推荐并聊下去 | 正 |
| 拒绝/换一个 | 拒绝这次推荐 | 负 |
| 不再推荐 | 明确说不想再听这类 | 进黑名单 |

| **触发方式** | **信号权重** | **理由** |
| --- | --- | --- |
| 孩子主动点播 | 1.0 | 最强的真实偏好 |
| 接受推荐后播放 | 1.0 | 主动选择 |
| 系统闲置推送 | 0.5 | 被动收听打对折，防止"系统推什么孩子就'喜欢'什么"的自我循环 |

上报只需带内容编号，标题、分类、实体标签由系统从内容库自动带出，设备端接入成本低。

## 六、回流规则：行为怎么变成记忆

规则全部量化，无解释空间：

| **规则** | **参数** |
| --- | --- |
| 同一实体加权正信号达 3 分，且无对应记忆 | 生成"喜欢××"候选记忆（初始置信度 65），带收听证据，进家长审核队列 |
| 正信号命中已有待确认记忆 | 置信度每次 +5×权重，**封顶 84，不自动越过确认线** |
| 正信号命中已确认记忆 | 只记一条调用记录，状态置信度都不动 |
| 拒绝命中待确认记忆 | 置信度每次 -5×权重，**保底 40，不清零**（孩子今天不想听 ≠ 不喜欢） |
| "不再推荐" | 实体进推荐黑名单，召回硬过滤；记忆状态不变；家长可随时解除 |
| 单次回流新增候选 | 最多 3 条，与"每周待确认 ≤3"的频控一致，不冲爆家长审核队列 |

三条铁律：

1. **状态变更只能家长做**——行为信号只调置信度，"待确认→已确认"永远走人工；

2. **回流幂等**——同一批事件只计一次，重复执行结果为零；

3. **对话内容不进回流**——已走抽取管道的证据不在行为管道再算一次。

## 七、推荐生成

**召回**：当前孩子可用记忆的实体 ∩ 内容标签（经层级展开）。

**硬过滤**，任何一条命中即不出：

1. 实体在"不再推荐"黑名单；

2. 家长设置的禁止主题；

3. 内容年龄区间不含孩子年龄；内容状态为屏蔽；

4. 敏感记忆规则（见 3.5），全部沿袭，不放宽。

**排序**：对话相关性 > 已确认且高置信 > 近期主动提及 > 未听过 > 未听完 > 频控去重 > 未被拒绝过。

**话术**：内容选什么由规则决定（可审计、可回归测试、敏感过滤不依赖模型自觉），大模型只负责把选定的内容说成一句适合孩子的话。每次推荐记录"用了哪条记忆、为什么推"，家长可查，反馈可精确归因。
